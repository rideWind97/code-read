在 React Fiber 架构中，判断“函数执行时间不够，需要中断”的核心机制是**时间切片（Time Slicing）**，主要依赖浏览器的调度能力，比如 `requestIdleCallback`、`MessageChannel` 等。

### 具体原理

1. **时间片分割**  
   React 会把渲染任务拆分成很多小单元（Fiber 节点），每次只处理一小部分。

2. **判断是否需要中断**  
   在每个小单元执行时，React 会检查当前帧还剩多少时间。如果时间快用完了，就会“中断”本次任务，把控制权还给浏览器，等下次有空闲再继续。

3. **如何判断时间是否足够（MessageChannel 重点）**  
   - `requestIdleCallback` 受浏览器实现和触发时机影响较大，不够稳定；React Scheduler 在浏览器环境通常用 `MessageChannel` 触发下一轮调度。
   - `MessageChannel` 的 `port.postMessage()` 会把回调放进“任务队列（macrotask）”，比 `setTimeout(fn, 0)` 更稳定、延迟更小，不依赖空闲回调。
   - React 会在每轮开始时记录 `startTime = performance.now()`，然后在循环里不断检查：
     `performance.now() - startTime >= timeSlice`（例如约 5ms）。
   - 一旦超过时间片预算，就 `shouldYieldToHost = true`，立即让出主线程，把剩余 Fiber 留到下一轮 `MessageChannel` 回调继续做。
   - 这不是“等浏览器完全空闲再做”，而是“做一小段就主动让出”，保证输入、动画、布局等高优任务有机会及时执行。

4. **中断与恢复**  
   - 如果发现时间不够，React 会保存当前 Fiber 树的遍历进度。
   - 下次调度时，从上次中断的地方继续。

### 代码层面（简化伪代码，接近 React Scheduler 思路）

```js
const channel = new MessageChannel();
const port = channel.port2;

let nextUnitOfWork = null;
const timeSlice = 5; // 每轮最多占用约 5ms
let startTime = 0;

function shouldYieldToHost() {
  return performance.now() - startTime >= timeSlice;
}

function workLoop() {
  startTime = performance.now();

  while (nextUnitOfWork && !shouldYieldToHost()) {
    nextUnitOfWork = performUnitOfWork(nextUnitOfWork);
  }

  if (nextUnitOfWork) {
    // 还没做完，投递下一轮宏任务继续
    port.postMessage(null);
  }
}

channel.port1.onmessage = workLoop;

function scheduleWork(rootFiber) {
  nextUnitOfWork = rootFiber;
  port.postMessage(null);
}
```

### MessageChannel 补充知识

- **为什么不用 microtask（Promise.then）？**  
  microtask 会在当前任务结束后立即清空，可能连续执行太久，不利于“及时让出”给渲染和输入事件。

- **为什么比 setTimeout 更常用？**  
  `setTimeout` 有最小延迟和节流问题（尤其后台标签页），`MessageChannel` 通常更适合做高频调度心跳。

- **React 真正判断是否让出的依据**  
  核心是“是否超过本轮预算 + 是否有更高优先级任务”，不是单纯看某个 API 的返回值。

### 总结

React 通过“时间切片”+“调度器”机制，使用 `MessageChannel` 驱动分段执行，并在每轮内通过 `performance.now()` 判断预算是否用完。时间不够就中断，下一轮继续，从而避免长任务阻塞主线程，提升交互流畅度。

**说明：**
- 每次 `workLoop` 只处理一小部分任务（一个或几个 Fiber 节点）
- 如果本轮预算用完（`performance.now() - startTime >= timeSlice`），就中断，下一轮继续
- 这样保证主线程不会被长任务长期占用，页面保持响应性

这就是 React Fiber 时间切片和中断的核心代码思想。
